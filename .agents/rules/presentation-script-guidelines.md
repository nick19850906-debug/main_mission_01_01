# 프로젝트 발표 대본 및 기술 설명 문서 작성 규칙

프로젝트 발표 대본, 포트폴리오 소개서, 또는 평가 대비 Q&A 문서를 작성할 때는 다음 원칙을 반드시 준수한다.

## 1. 원래 과제 요구사항 최우선 집중 (80% 이상 비중)
- 발표 대본의 핵심 내용은 **원래 부여된 과제(Mission)의 필수 평가 기준 및 기술적 요구사항**을 논리정연하게 증명하는 데 집중한다.
- 반드시 강조해야 할 핵심 기술 요소:
  1. **웹 표준 & 시맨틱 마크업**: 태그 위계 설계(`header`, `nav`, `main`, `section`, `article`, `footer`), SEO 최적화
  2. **웹 접근성(a11y)**: 스킵 네비게이션, `aria-*` 속성 동기화, 명시적 `label for`, 44px 이상 터치 표적 확보
  3. **반응형 레이아웃**: Mobile-First 브레이크포인트, 1차원 Flexbox vs 2차원 CSS Grid의 명확한 기술 선택 근거
  4. **단방향 상태 관리 (Mental Model)**: "이벤트(Event) → 상태 변경(State) → 화면 렌더링(DOM)" 흐름과 불변성 유지
  5. **비동기 통신 및 4대 상태 분기**: 로딩(Loading), 성공(Success), 에러(Error & Retry), 빈 데이터(Empty) 처리 및 타임아웃
  6. **폼 실시간 유효성 검사**: 정규식(Regex) 검증, 인라인 에러 피드백, 자동 포커스 이동 UX
  7. **브라우저 성능 최적화**: 스크롤 Throttle, Intersection Observer `unobserve` 등

## 2. 심미적/시각적 부가 효과의 적절한 비중 조절 (10~15% 내외)
- 배경 파티클, 플로팅 코드, 모멘텀 스크롤, 맥동 애니메이션 등 시각적 효과는 부가적인 요소이다.
- 대본 전체를 시각 효과로 도배하지 말 것.
- 도입부나 보조 설명에서 *"브라우저의 동적 렌더링 및 인터랙션 역량을 입증하기 위해 구현했다"* 정도로 가볍게 1~2문장만 짚고 넘어가며, 주된 시간은 핵심 기본기와 문제 해결 로직을 설명하는 데 배분한다.

## 3. 시연 행동 가이드라인([시연 행동]) 명시
- 발표자가 실제 브라우저 화면을 띄워두고 자연스럽게 조작할 수 있도록 각 문단 사이에 `[시연 행동: 브라우저 너비를 줄여 Grid 반응형 시연]`과 같은 명확한 행동 지침을 포함한다.

## 4. 평가관 예상 질문 및 즉답 카드(Bonus Q&A) 제공
- 발표 종료 후 이어질 수 있는 기술적 질문("왜 Flexbox와 Grid를 분리했는가?", "왜 바닐라로 상태관리를 구현했는가?")에 대해 핵심을 찌르는 모범 답변을 치트시트 형태로 함께 제공한다.
